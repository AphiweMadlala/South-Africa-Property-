# Extraction runbook — Phases 1–2

How to go from nothing to a normalised, deduplicated, provenance-tracked dataset
of the @southafrica.property archive. Every step writes files that later steps
read; nothing is typed in by hand.

## 0. Environment prerequisites

The first session could not run any of this: its network policy denied every
host below (see [`research/00-access-log.md`](research/00-access-log.md)).

| Need | Why |
| --- | --- |
| `api.apify.com` | Apify API — actor runs and datasets |
| `www.instagram.com`, `i.instagram.com` | Reconnaissance, spot-checking the profile |
| `*.cdninstagram.com`, `*.fbcdn.net` | Downloading the images Apify returns (signed CDN URLs) |
| `r.jina.ai` | Agent Reach web reader (optional) |
| Listing portals and agency sites named in captions | Verifying current availability (optional; see the status model) |
| `APIFY_TOKEN` environment variable | Apify CLI authentication |

Environment variables and network changes apply to a **new** session.

## 0b. Or: run the extraction on GitHub

If the build environment can't reach Apify, the workflow
`.github/workflows/extract-instagram.yml` runs steps 2–3 on GitHub's machines
and commits the results (raw export, normalised data, media, analysis) to the
branch:

1. Add the repository secret `APIFY_TOKEN` (Settings → Secrets and variables →
   Actions). The token is under Apify Console → Settings → API & Integrations.
2. Push `.github/extract-request.json` on a `claude/*` branch with
   `{ "limit": 200, "confirmCost": false }`. This runs a dry run only. Read the
   pricing in the run log and estimate the cost.
3. After the cost is confirmed, push the file again with `"confirmCost": true`.
   Once the workflow file is on `main`, "Run workflow" on the Actions tab does
   the same.
4. `git pull` the branch and continue with step 4 below.

## 1. Reconnaissance (Agent Reach)

```bash
agent-reach doctor --json                      # if the CLI is installed
curl -s "https://r.jina.ai/https://www.instagram.com/southafrica.property/"
```

Then search the web for the account's bio link, any website, and other
platforms it names. Record findings in `documentation/research/01-reconnaissance.md`,
separating verified facts from inference.

## 2. Apify extraction

```bash
npm ci
npm i -g apify-cli                              # v1.5+; v1.10.0 verified
scripts/extract/apify-extract.sh                # dry run: auth, input keys, pricing
```

Check the dry run before spending anything:

- the input keys include `usernames` (profile scraper), `username` and
  `resultsLimit` (post and reel scrapers) — if an actor renamed them, edit the
  `*_INPUT` lines in the script;
- no actor is deprecated;
- cost: multiply each per-event price by the volume (1 profile, ≤ 200 posts,
  ≤ 200 reels). Warn above $5; get explicit confirmation above $20. Estimates
  are rough — the Apify billing dashboard is the truth.

```bash
CONFIRM_COST=1 scripts/extract/apify-extract.sh
```

This writes `data/raw/instagram/<UTC stamp>/` containing `profile.json`,
`posts.json`, `reels.json`, the run metadata (`*.run.json`) and
`extraction.json`. The directory is made read-only. **Raw exports are never
edited or overwritten**; a re-extraction creates a new stamped directory.

## 3. Normalise, fetch media, hash, dedupe — straight away

Instagram CDN URLs are signed and expire within days, so run these in the same
session as the extraction:

```bash
npm run extract:normalize     # → data/normalized/posts.json, profile.json
npm run media:fetch           # → media/source/<post>/<nn>.jpg + media/manifest.json
npm run media:hash            # → media/hashes.json
npm run extract:dedupe        # → data/normalized/residences.json
node scripts/research/archive-analysis.mjs   # → documentation/research/02-archive-analysis.md
```

`media:fetch` is idempotent; re-run it to retry failures listed in
`media/manifest.json → failures`. A `403`/`410` means the signed URL expired:
re-extract rather than guessing.

## 4. Review before modelling content

- Read `documentation/research/02-archive-analysis.md` — it answers most Phase 1
  questions (content mix, cadence, credits, CTAs, geography, vocabulary) with
  measured numbers.
- Open every cluster in `residences.json` with `needsReview: true` and every
  entry in `rejected`. Confirm or split them; record decisions in
  `data/normalized/dedupe-decisions.json` (post pairs + reason) so the
  decision survives re-runs.
- Spot-check 10 random posts against Instagram: caption, date, media count.

Then continue with [`content-model.md`](content-model.md), design and build, and
deploy as described in [`deployment.md`](deployment.md).

## Media storage

Originals live in `media/source/`. Commit the originals of every residence the
site uses (the CDN copies will expire), and only those. If the full archive is
under ~150 MB it can all be committed; otherwise keep unused originals out of
git. Web derivatives (AVIF/WebP, responsive widths) are generated by the site
build from these originals.

## Troubleshooting

| Symptom | Likely cause | Action |
| --- | --- | --- |
| `You are not logged in` | `APIFY_TOKEN` not set in this session | Add it to the environment; start a new session |
| Empty dataset | Anti-bot block or wrong input key | Check input keys; enable Apify Proxy in the input; read `apify actors info <actor> --readme` |
| Fewer reels than expected | The post scraper under-counts reels | The reel scraper output is merged by shortcode |
| `HTTP 403/410` on media | Signed CDN URL expired | Re-extract, then fetch immediately |
| Likes are `null` | Owner hides like counts (Apify reports -1) | Expected; not an error |
